# Windows GUI 명세

## 기술 선택

**PyQt5 + QWebEngineView.** 창과 위젯(폴더 목록, 옵션 입력)은 네이티브 Qt 위젯으로 만들고,
결과 리포트만 `QWebEngineView`에 `report/html.py`가 만든 HTML을 그대로 그린다.

이유: 결과 리포트가 이미 HTML/CSS/JS(검색 기능 포함)로 완성되어 있다. 이 부분을 다시 위젯으로
짜지 않고 `QWebEngineView`에 그대로 붙인다. 반면 폴더 목록·옵션 입력처럼 파일 시스템과
자주 상호작용하는 부분은 네이티브 Qt 위젯(드래그앤드롭, 파일 다이얼로그, 스레드)이 더 다루기 쉽다.

> 이전에는 pywebview 단일 창으로 설계했으나, PyQt5 기반으로 결정을 변경했다. 32비트 Python
> 환경에서도 PyQt5는 win32 휠이 배포되어 설치·개발·검증이 가능하다는 점도 이유 중 하나였다
> (PyQt6/Qt6는 win32를 지원하지 않는다). docs/ROADMAP.md 결정 기록 참고.

파이썬 ↔ 리포트 뷰 사이에는 JS 브릿지가 없다. 리포트는 순수 정적 HTML(내장 검색 JS만 있음)이고,
저장 버튼은 GUI가 마지막으로 만든 HTML 문자열을 그대로 파일에 쓴다.

## 화면

단일 창, 세로 3단 (`QVBoxLayout` 안에 `QGroupBox` 3개). 최소 크기 900×600, 기본 1200×800.

│  파일 패턴 [*.json    ]  ☐ 하위 폴더 포함                   │
│  배열 매칭 키 [id      ]  ☐ 차이 없는 파일 숨기기           │

## 동작

**폴더 추가** — "폴더 추가" 버튼은 `QFileDialog.getExistingDirectory` (한 번에 하나).
창 전체와 폴더 목록(`FolderListWidget`)이 드롭 대상이라, 탐색기에서 폴더 여러 개를
끌어다 놓으면 `dropEvent`에서 URL마다 `Path.is_dir()`을 검사해 한꺼번에 추가한다.
폴더가 아닌 항목은 조용히 무시한다.

**개수 제약 없음** — 폴더는 정확히 5개가 아니라 2~N개(제한 없음) 추가할 수 있다. 목록은
`QListWidgetItem`을 하나씩 추가/삭제하는 구조라 개수에 대한 가정이 코드에 없다.

**순서** — `FolderListWidget`은 `QListWidget.InternalMove` 드래그 재정렬을 쓴다.
목록 순서 = `folder_paths()`가 돌려주는 순서 = 리포트의 열(라벨) 순서.

**중복** — 같은 절대경로를 두 번 추가하면 `has_path()`가 걸러내고, 기존 행을 선택해서
`flash_item()`으로 강조한다.

**실행** — 폴더가 2개 미만이면 "비교 실행" 버튼을 비활성화하고, 상태 라벨에
"폴더를 2개 이상 추가하세요 (현재 N개)"를 띄운다. 비교는 `CompareWorker`(QThread)에서 돌고
UI를 막지 않는다. 진행 중에는 버튼 텍스트가 "비교 중… (12/40 파일)"로 바뀐다("취소" 버튼 노출).

**같은 이름 파일끼리만 비교** — `engine.inventory.collect_files`가 폴더들의 파일명 합집합을
만들고, `engine.compare.compare_file`은 그 파일을 실제로 가진 폴더(`live_labels`)끼리만
비교한다. 어떤 폴더에도 없는 파일명은애초에 인벤토리에 없으므로 비교 대상이 아니다.

**없는 파일 안내** — 파일이 일부 폴더에만 있으면 `FileReport.absent_in`에 나머지 폴더가
담기고, 리포트의 해당 파일 섹션 맨 위에 "이 파일이 없는 폴더: ..." 노트로 표시된다.
(engine 쪽 규약은 `docs/SPEC-engine.md` 2절 참고.)

**결과** — 리포트를 임시 파일로 쓰고 `QWebEngineView.load(file://…)`로 연다
(`MainWindow._show_html`). 검색·접기는 리포트에 이미 들어있는 JS가 처리하므로 GUI 쪽에서
다시 구현하지 않는다. 실행할 때마다 이전 결과를 완전히 교체한다.

> `setHtml()`을 쓰지 않는 이유: 내용을 data: URL로 바꿔 넣는데 그 URL이 2MB로 제한되어,
> 그보다 큰 리포트는 **아무 오류 없이 빈 화면**이 된다. 폴더 10개 × 파일 200개면 리포트가
> 2.3MB가 되어 실제로 걸린다. 회귀 방지 테스트는 `tests/test_ui_report_view.py`.
> 파일로 여는 방식은 charset을 가정하지 않으므로, 화면에 띄우는 HTML에는 반드시
> `<meta charset="utf-8">`가 있어야 한글이 안 깨진다.

**저장** — HTML은 마지막으로 렌더링한 문자열을 그대로 쓴다. CSV는
`파일명, 경로, 차이유형, 폴더, 값` 한 행 단위로 쓰고 Excel 한글 깨짐을 막기 위해
`utf-8-sig`로 저장한다 (`report/csv_export.py`).

**프리셋** — 폴더 목록과 옵션 한 벌(`settings.Session`)을 이름 붙여 저장한다. 저장 위치는
`%APPDATA%\JsonFolderDiff\presets.json` (`settings.settings_path`). 창을 닫을 때 현재 상태를
`last_session`으로 자동 저장하고, 다음 실행 때 복원한다.

설정 파일이 없거나 깨져 있어도 예외를 올리지 않고 기본값으로 뜬다. 모르는 옵션 키는 버린다.
설정 때문에 프로그램이 못 뜨는 일은 없어야 한다(`settings.load_settings`).

**사라진 폴더** — 프리셋에 적힌 폴더가 없어졌으면 목록에서 지우지 않고 회색으로 두고
"(폴더 없음 — 비교에서 제외)"를 붙인다. 사용자가 경로를 보고 직접 판단할 수 있어야 한다.
비교는 `existing_folder_paths()`만 대상으로 하고, 실행 버튼의 "2개 이상" 판정도
살아있는 폴더만 센다.

**취소** — `CompareWorker.cancel()`이 내부 플래그를 세우고, 파일 단위 루프 사이에서
확인해 남은 파일을 처리하지 않고 조용히 끝낸다(신호를 emit하지 않음). UI는 스레드가 실제로
멈출 때까지 기다린 뒤에(`QThread.wait`) 버튼을 되살린다. 기다리지 않으면 아직 파일을 읽는
워커를 남겨둔 채 다음 실행이 시작된다.

**창 닫기** — `closeEvent`에서 같은 방식으로 워커를 멈춰 기다리고, 결과 표시용 임시 폴더를
지운다. 이 처리가 없으면 비교가 도는 중에 창을 닫았을 때 스레드가 살아있는 채로 앱이 끝난다.

## 빈 화면과 오류

- 첫 실행: 결과 영역에 "폴더를 2개 이상 추가하고 비교를 실행하세요." (`PLACEHOLDER_HTML`)
- 차이 없음(또는 `only_diff` 옵션으로 전부 걸러짐): "선택한 폴더들의 JSON 내용이 모두
  같습니다." (실패가 아니라 정상 결과로 보이게)
- 패턴에 맞는 파일 0개: `CompareWorker.failed` 시그널로 메시지박스에 어떤 패턴으로 찾았는지
  알린다.
- 파싱 실패: 창 전체를 막지 않는다. 해당 파일 섹션 안에 `errors`로 표시된다
  (engine이 이미 폴더 단위로 격리해서 처리).

## Windows 특이사항

- 경로 260자 제한. 긴 경로는 실패 시 그 파일만 `errors`로 처리한다(엔진 쪽 예외 처리 규약과 동일).
- 한글·공백·네트워크 경로(`\\server\share`)를 테스트에 포함한다.
- 창 제목: `JSON Folder Diff`.
- 고DPI 스케일링에서 레이아웃이 깨지지 않는지 125% / 150%로 확인한다. PyQt5는
  `Qt.AA_EnableHighDpiScaling`을 켜야 자동 스케일링이 동작한다 (`app.py` 참고).
